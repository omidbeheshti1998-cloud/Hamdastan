# مرحلهٔ علایق (STEP 3)

مرحلهٔ سوم ثبت‌نام، بعد از نام و نام خانوادگی و پیش از
[کوییز ترجیحات](./PREFERENCES.md). هدف این است که علایق کاربر را
**بدون حس پرسشنامه** بگیریم: بدون Slider، بدون امتیاز عددی، بدون سؤالِ
«چقدر علاقه داری؟».

> **وضعیت: به بک‌اند وصل است.** بخش [اتصال به بک‌اند](#اتصال-به-بک‌اند) را ببین.

| | |
|---|---|
| کامپوننت | `app/_login/_steps/interests-step.tsx` |
| دیتای دسته‌ها | `lib/interests.ts` |
| ذخیره‌سازی (seam) | `saveInterests` در `lib/auth/client.ts` |

---

## مدل تعامل

```
دسته را بزن → انتخاب می‌شود → همان کارت باز می‌شود → زیرعلاقه‌ها را بزن
```

- در هر لحظه **فقط یک دسته باز** است؛ باز کردن دستهٔ جدید قبلی را می‌بندد.
- بستن یک دسته **انتخاب‌هایش را پاک نمی‌کند**.
- انتخاب زیرعلاقه کاملاً اختیاری است؛ دسته به‌تنهایی هم معتبر است.
- زدن دوبارهٔ یک chip آن را از انتخاب درمی‌آورد.
- کل صفحه اسکرول می‌شود؛ داخل هیچ کارتی اسکرول مستقل نیست.

### چرا دکمهٔ ✕ جداگانه؟

هدرِ کارت یک دکمه است که «انتخاب + باز کردن» و بعد از آن «باز/بسته کردن» را
انجام می‌دهد. اگر همان دکمه انتخاب را هم برمی‌داشت، کاربری که فقط می‌خواست کارت
را ببندد، زیرعلاقه‌هایش را از دست می‌داد. پس **لغو انتخاب** یک دکمهٔ ✕ مستقل
دارد که فقط روی دسته‌های انتخاب‌شده دیده می‌شود.

### حالت انتخاب‌شده

کارت انتخاب‌شده حاشیهٔ پررنگ و تیکِ پرشده می‌گیرد، و در حالت بسته تعداد
زیرعلاقه‌ها را نشان می‌دهد:

```
✓ ورزش                      ۳ انتخاب   ⌄   ✕
```

## قاعدهٔ حداقل انتخاب

حداقل **۳ دسته** برای ادامه لازم است (`MIN_INTEREST_CATEGORIES` در `lib/interests.ts`).

| وضعیت | Hint | CTA |
|---|---|---|
| کمتر از ۳ دسته | «حداقل ۳ علاقه رو انتخاب کن.» | «حداقل ۳ مورد انتخاب کن» — غیرفعال |
| ۳ دسته یا بیشتر | «عالیه! هرچقدر دوست داری می‌تونی ادامه بدی.» | «ادامه» — فعال |

CTA در پایین صفحه `sticky` است و هنگام ذخیره به «در حال ذخیره...» می‌رود و
قفل می‌شود. کنارش یک اکشن کم‌رنگ‌تر «فعلاً رد کردن» هست که مرحله را می‌پراند.

## Interest Score — فقط بک‌اند

اگر بک‌اند به امتیاز علاقه نیاز دارد، **خودش از انتخاب خام حساب می‌کند**:

```
score(category) = min(5 + تعداد زیرعلاقه‌های انتخاب‌شده, 10)
```

مثال: `ورزش + فوتبال + بدنسازی + کوهنوردی` → `5 + 3 = 8` از ۱۰.

این امتیاز **هرگز در UI نمایش داده نمی‌شود**.

فرانت عمداً این را حساب نمی‌کند و نمی‌فرستد: امتیازی که از مرورگر بیاید قابل
جعل است و نگه داشتنش در دو جا باعث واگرایی منطق می‌شود. فرانت فقط انتخاب خام را
می‌فرستد.

## قرارداد داده

`lib/interests.ts` هر دسته و زیرعلاقه را با یک `id` پایدار و یک `label` فارسی
تعریف می‌کند. **آنچه به بک‌اند می‌رود `id` است، نه برچسب** — تا تغییر متن فارسی
قرارداد داده را نشکند.

`id` زیرعلاقه فقط داخل دستهٔ خودش یکتاست، پس `other` در همهٔ دسته‌ها تکرار
می‌شود و `startup` هم در `technology` و هم در `business` هست.

شکل انتخاب در state و در payload:

```ts
type InterestSelection = Record<string, string[]>;

// نمونه
{
  "sports":     ["football", "bodybuilding", "mountaineering"],
  "technology": ["ai", "programming"],
  "music":      []            // دسته انتخاب شده، بدون زیرعلاقه
}
```

حضور کلید یعنی دسته انتخاب شده است؛ آرایهٔ خالی کاملاً معتبر است.

## اتصال به بک‌اند

مثل بقیهٔ فلو، فرانت فقط به بک‌اند داخلی درخواست می‌دهد
(قاعده در [`docs/AUTH.md`](./AUTH.md#اتصال-به-بک‌اند)):

| تابع | مسیر داخلی | هویت |
|---|---|---|
| `saveInterests` | `POST /api/onboarding/interests` | کوکی نشست |

پیاده‌سازی: [`app/api/onboarding/interests/route.ts`](../app/api/onboarding/interests/route.ts)

- کاربر از کوکی نشست می‌آید؛ تابع اصلاً شماره نمی‌گیرد.
- قاعدهٔ حداقل ۳ دسته سمت سرور هم اعمال می‌شود؛ کلاینت فقط CTA را قفل می‌کند.
- `id` ناشناخته کل درخواست را رد می‌کند (`400`)، نه اینکه بی‌صدا حذف شود —
  `id` ناشناخته یعنی قرارداد داده شکسته و بی‌صدا رد کردنش آن را پنهان می‌کند.
- هر بار کل انتخاب جایگزین می‌شود، نه اینکه روی قبلی اضافه شود؛ «حذف یک دسته»
  جز این شکل دیگری ندارد.
- «فعلاً رد کردن» هیچ درخواستی نمی‌زند؛ اگر لازم شد بدانیم کاربر رد کرده، یک
  endpoint جدا می‌خواهد.

### دیتابیس

`user_interest_categories` و `user_interest_subs` — دو جدول، چون «دسته انتخاب
شده، بدون زیرعلاقه» حالت معتبری است و کلید خارجی مرکب جلوی زیرعلاقهٔ بی‌دسته را
می‌گیرد. Interest Score ذخیره نمی‌شود و با همین کوئری از داده درمی‌آید:

```sql
SELECT c.category_id, least(5 + count(s.sub_id), 10) AS score
FROM user_interest_categories c
LEFT JOIN user_interest_subs s USING (user_id, category_id)
WHERE c.user_id = $1
GROUP BY c.category_id;
```

جزئیات بیشتر در [`docs/DATABASE.md`](./DATABASE.md).

## نکات فنی

**انیمیشن باز/بسته شدن** با ترفند `grid-template-rows: 0fr ↔ 1fr` انجام می‌شود
(۲۰۰ms، داخل بازهٔ ۱۵۰–۲۵۰ms خواسته‌شده). مزیتش این است که ارتفاع را لازم نیست
با JS اندازه بگیریم و هر دو جهت نرم انیمیت می‌شود. عنصر داخلی حتماً باید
`overflow-hidden` داشته باشد، وگرنه گرید زیر اندازهٔ محتوا جمع نمی‌شود.
با `motion-reduce:transition-none` هم احترام به تنظیم کاربر حفظ شده است.

**پنل بسته `inert` می‌گیرد.** چون محتوا در DOM می‌ماند و فقط clip می‌شود، بدون
`inert` chip های نامرئی هنوز با Tab فوکوس می‌گرفتند و در درخت دسترس‌پذیری بودند.
