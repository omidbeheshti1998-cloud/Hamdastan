# مرحلهٔ ترجیحات (کوییز کوتاه)

بعد از مرحلهٔ علایق. هدف گرفتن چند Preference ساده برای شخصی‌تر کردن تجربه است —
**نه تست شخصیت و نه پرسشنامه**. حس مورد نظر: «چند انتخاب کوتاه»، حدود
۲۰ تا ۳۰ ثانیه.

> **وضعیت فعلی: فقط UI.** ذخیره‌سازی هنوز Mock است — بخش
> [اتصال به بک‌اند](#اتصال-به-بک‌اند) را ببین.

| | |
|---|---|
| کامپوننت | `app/_login/_steps/preferences-step.tsx` |
| سؤال‌ها و محورها | `lib/preferences.ts` |
| ذخیره‌سازی (seam) | `savePreferences` در `lib/auth/client.ts` |

---

## ساختار

سه فاز داخل یک کامپوننت: `intro → quiz → done`.

```
intro ──▶ سؤال ۱ … سؤال ۷ ──▶ completion ──▶ مرحلهٔ بعد
  │              │                  │
  └──────────────┴──── «فعلاً رد کردن» ─────▶ مرحلهٔ بعد
```

- **یک سؤال در هر صفحه**، دقیقاً ۳ گزینه، بدون دکمهٔ «ادامه».
- انتخاب گزینه → Selected State → **۲۵۰ms بعد** سؤال بعد خودکار باز می‌شود.
- «قبلی» به سؤال قبل برمی‌گردد و پاسخ قبلی همچنان Selected است و قابل تغییر.
  روی سؤال اول، «قبلی» به intro برمی‌گردد.
- «فعلاً رد کردن» در intro و همهٔ سؤال‌ها هست و **کل کوییز** را رد می‌کند.
- بالای هر سؤال «۳ از ۷» و یک نوار پیشرفت ۴ پیکسلی.

---

## قواعدی که نباید شکسته شوند

هیچ‌کدام از این‌ها نباید وارد UI شود:

- Slider، Rating، امتیاز عددی
- آیکون، ایموجی، تصویر یا نماد **داخل گزینه‌ها** (گزینه‌ها فقط متن‌اند)
- برچسب محورها: «درون‌گرا»، «برون‌گرا»، «منطقی»، «احساسی»، «ریسک‌پذیر»، «محتاط»
- هر نتیجه یا تحلیلی بعد از پاسخ‌ها — نه درصد، نه امتیاز، نه توصیف شخصیت
- Modal یا تأیید بعد از هر پاسخ

### گزینهٔ میانه

گزینهٔ سوم هیچ‌وقت «متعادل» یا «خنثی» نیست. متنش به موقعیت همان سؤال بستگی
دارد — «بستگی داره»، «هر دو»، «هر دو برام مهمه» — تا یک انتخاب واقعی به نظر
برسد، نه پاسخ درجه‌دو.

## قرارداد داده

هر سؤال یک **محور (dimension)** است. `id` سؤال نام همان محور است و فقط برای
بک‌اند؛ هیچ‌وقت رندر نمی‌شود.

| `id` | محور | ‎-1 | +1 |
|---|---|---|---|
| `introversion-extroversion` | Introversion ↔ Extroversion | با خودم باشم | با بقیه وقت بگذرونم |
| `logic-feeling` | Logic ↔ Feeling | واقعیت و منطق | حس خودم و آدم‌ها |
| `planning-spontaneity` | Planning ↔ Spontaneity | از قبل برنامه می‌چینم | همون موقع تصمیم می‌گیرم |
| `competition-collaboration` | Competition ↔ Collaboration | رقابت | همکاری |
| `caution-risk-taking` | Caution ↔ Risk Taking | مطمئن می‌شم | امتحانش می‌کنم |
| `detail-big-picture` | Detail Oriented ↔ Big Picture | جزئیات | تصویر کلی |
| `realistic-imaginative` | Realistic ↔ Imaginative | عملی و شدنی | ایده‌ها و امکان‌ها |

مقدار هر پاسخ: **`-1`** گرایش به گزینهٔ اول، **`0`** میانه، **`+1`** گرایش به
گزینهٔ دوم.

```ts
type PreferenceAnswers = Record<string, -1 | 0 | 1>;

// نمونه
{
  "introversion-extroversion": -1,
  "logic-feeling": 0,
  "planning-spontaneity": 1,
  …
}
```

## اتصال به بک‌اند

مثل بقیهٔ فلو، فرانت فقط به بک‌اند داخلی درخواست می‌دهد
(قاعده در [`docs/AUTH.md`](./AUTH.md#اتصال-به-بک‌اند)):

| تابع | مسیر داخلی موردنظر |
|---|---|
| `savePreferences` | `POST /api/onboarding/preferences` |

نکات پیاده‌سازی:

- ذخیره فقط یک بار و در انتها انجام می‌شود — وقتی کاربر روی «بزن بریم» بزند.
  اگر Skip کند هیچ درخواستی نمی‌رود، حتی اگر چند سؤال جواب داده باشد.
- پاسخ ناقص هم ممکن است نیاید؛ کلید نبودن یعنی بی‌پاسخ.
- `id` های ناشناخته و مقادیر خارج از `{-1, 0, 1}` را رد کن.
- اگر از این داده برچسب یا امتیاز شخصیتی ساخته می‌شود، **نباید به فرانت
  برگردد** — این مرحله هیچ نتیجه‌ای نشان نمی‌دهد.

### دیتابیس

هیچ اسکیمایی در این تغییر ساخته یا مهاجرت نشده است. هر تغییر دیتابیسی باید
به‌صورت کوئری برای اجرا به صاحب پروژه داده شود.

## نکات فنی

**قفل در فاصلهٔ auto-advance.** بین انتخاب گزینه و باز شدن سؤال بعد ۲۵۰ms فاصله
است؛ در این فاصله `advancing` ورودی را قفل می‌کند، وگرنه تپ دوم کاربر روی همان
نقطه، گزینهٔ سؤال بعد را هم انتخاب می‌کرد و یک سؤال پریده می‌شد. `goBack` هم
همین قفل را چک می‌کند.

**تایمر در unmount پاک می‌شود** تا اگر کاربر وسط فاصله Skip کرد، `setState` روی
کامپوننت unmount شده اجرا نشود.

**ترنزیشن بین سؤال‌ها** همان `animate-step-in` مشترک با بقیهٔ مراحل است، با
`key={question.id}` تا هر سؤال دوباره اجرا شود. کوتاه و بدون افکت نمایشی.
